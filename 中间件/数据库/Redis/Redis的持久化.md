### 1、持久化

Redis的持久化有两种方式：RDB和AOF以及其混合模式。

#### 1.1 RDB: Redis DataBase

RDB文件是经过压缩的二进制文件，通过该文件可以还原生成RDB文件时的数据库状态。RDB持久化可以手动执行，也可以根据配置定期执行。

生成RDB文件有两个命令：`SAVE` 和 `BGSAVE`。

- SAVE会阻塞服务器进程，直到RDB文件创建完完成。
- BGSAVE会fork一个子进程来负责创建RDB文件，不阻塞服务器进程。
服务器内部维护了一个dirty计数器和lastsave属性：

- dirty：记录了距上次成功执行了SAVE或BGSAVE命令之后，数据库修改的次数（写入、删除、更新等）；
- lastsave：unix时间戳，记录了上一次成功执行SAVE或BGSAVE命令的时间；
服务器会周期性（默认每100ms）地检查配置所设置的保存条件（间隔秒数和修改次数，【个人理解这里有可能会丢数据】）是否满足，如果满足就执行SAVE/BGSAVE命令。检查的过程：根据系统当前时间、dirty和lastsave属性的值来检验保存条件是否满足。
载入RDB文件期间，服务器会一直处于阻塞状态。
服务器开启了AOF持久化功能时，会优先使用AOF文件来还原数据库状态，否则使用RDB文件还原。


#### 1.2 AOF: Append Of File

AOF是将服务器执行的写命令以追加的方式保存到AOF文件中。

AOF持久化功能包括三个步骤：0

- 命令追加（append）：将写命令追加到aof_buf缓冲区的末尾；
- 文件写入：服务器结束每个事件之前，都会检查是否需要将aof_buf缓冲区内容写入AOF文件；
- 文件同步（sync）：和文件写入的实现是一起的，同步方式有三种，由appendfsync选项决定：
  - always：将缓冲区中的所有内容写入AOF文件并同步；
  - everysec：将缓冲区中的所有内容写入AOF文件，如果距离上次同步时间超过一秒，就再对AOF文件进行同步，并且由专门的线程负
  - no：将缓冲区中的所有内容写入AOF文件，但不同步，由操作系统同步。


#### 1.3 RDB + AOF：混合持久化

由于单纯RDB的话，可能存在数据的丢失，而频繁的AOF又会影响了性能，在Redis4.0之后，支持了混合持久化，也就是每次启动时候通过RDB+增量的AOF文件来进行回复，由于增量的AOF仅记录了开始持久化到持久化结束期间发生的增量，这样日志不会太大，性能相对较高。

### 3、AOF的重写
命令是`BGREWRITEAOF`，为了解决AOF文件体积膨胀的问题。创建一个新的AOF文件来替代现有的AOF文件，数据库状态相同，新AOF文件会去掉冗余的写命令，体积要小得多。

实现方法是创建一个子进程遍历数据库所有key，生成对应写命令写入文件。为了避免在执行命令时造成客户端输入缓冲区溢出，一个键包含多个元素且超过`REDIS_AOF_REWRITE_ITEMS_PER_CMD`（一般为64）常量时，重写程序会使用多条命令记录键的值。

为了解决数据不一致的问题，服务器设置一个AOF重写缓冲区，当执行完一个写命令之后，会同时将这个写命令发送给AOF缓冲区和AOF重写缓冲区，如下图。
