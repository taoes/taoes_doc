### 1. WebHook ?
*Webhook* 这一名称取自 *Web*（表明指的是基于 HTTP 的通信）与 *hooking* 编程函数（允许应用截获调用或可能感兴趣的其他事件）。Webhook 可“钩住”服务器应用上发生的事件，并提示服务器通过 Web 将有效负载发送到客户端.
优点:
1. 实时性
2. 低耦合度
3. 节省资源(相对于WebSocket & 轮询而言)
4. 灵活性

缺点:
1. 在公网环境中可能面临DDNS等安全性问题
2. 可靠性: 可能面临事件丢失,因此需要一定的机制去补偿这部分数据,保障数据一致性
3. 复杂性: 管理WebHook可能比较复杂,特别是对安全要求较高的公司
4. 回执问题: 并不保证消息消费成功,缺少MQ等中间的ACK机制

### 2. WebHook 注意事项

- 订阅的事件数应尽可能少
- 使用 Webhook 加密
- 2.3 使用 HTTPS 和 SSL 验证
- 允许WebHook的 IP 地址
- 在 10 秒内进行响应: 异步处理
- 在处理事件之前检查事件类型和操作
- 重新传递遗漏的传递 如果请求重新交付，X-Delivery 标头将与原始交付的标头相同。



### 3. Web经典的使用场景

- OSS上传回调通知
- 支付结果回调
- 异常告警
- 客户服务
- 物联网服务
